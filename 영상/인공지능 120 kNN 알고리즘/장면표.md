# kNN 알고리즘 영상 장면표

## 공통 규칙

- **읽기** 줄은 타입캐스트에 넣는 문장이에요. 자막은 읽기 줄에서 아래 표기 규칙으로 바꿔 만들어요.
- 화면 속 숫자는 모두 원고에 있는 값만 써요. 새 숫자를 만들지 않아요.
- `{천천히: …}` 부분은 따로 만들어 천천히 읽어요(audio_tempo 0.8, 앞 문장과 0.35초 쉼). 영상마다 핵심 용어를 처음 소개할 때 한 번만 써요.
- 계산 과정(거리 12개 전체 표, 정규화 계산)은 영상에서 결과만 보여 주고 블로그로 넘겨요.
- 쇼츠는 말이 끝나면 길게 쉬지 않고 0.8초 안에 끝내요. 끝 안내 화면은 마지막 문장을 말하는 동안 띄워요.
- 쇼츠 끝을 롱폼과 다르게 하고 싶으면 쇼츠 전용 장면(S…)을 따로 둬요. 쇼츠는 다음 내용이 궁금해지는 질문으로 끝내요.
- **쇼츠** 칸에 표시된 장면은 세로 배치로 다시 출력해 쇼츠로 써요.
- **멈춤** 줄이 있으면 그 장면 음성 뒤에 그만큼 말없이 화면만 보여 줘요(맞혀 보기 시간).

### 표기 규칙 (읽기 → 자막)

- `[읽는 소리|자막 글자]`: 그 자리만 따로 바꿔요. 예: `[케이|k]`, `[영 점 이팔|0.28]`
- `{천천히: …}`: 그 부분만 천천히 읽어요.
- 아래 표의 단어는 어디에 나오든 자동으로 바꿔요.

| 읽기 | 자막 |
| --- | --- |
| 케이엔엔 | kNN |
| 케이디 트리 | KD 트리 |
| 일래스틱서치 | Elasticsearch |
| 애노이 | Annoy |
| 에벌린 픽스 | Evelyn Fix |
| 조지프 호지스 | Joseph Hodges |

## 장면

### L01 · 여는 질문 (쇼츠 S1 시작 후보)

- 읽기: 처음 보는 음식을 보고 "이건 그 친구가 좋아하겠다" 하고 바로 떠오른 적 있죠? 그 생각을 그대로 계산으로 옮긴 방법이 있어요. 오늘 배울 건 가까운 이웃에게 물어보는 방법, {천천히: [케이, 엔, 엔.|kNN] 알고리즘이에요.}
- 화면: 물음표가 붙은 음식 접시 하나 → 제목 「kNN: 가까운 이웃에게 물어보기」
- 움직임: 접시가 튀어 오르듯 등장, 제목 글자가 아래에서 올라옴

### L02 · 채널 인사 (공통 인트로)

- 읽기: 안녕하세요, [눈바공 연구소|눈바공 연구소] [바닥 연구소장입니다.|바닥 연구소장입니다.]
- 화면: 채널 전체 이름 「눈높이가 바닥에 있는 공학 연구소」에서 눈·바·공 세 글자 강조 → 세 글자가 모여 「눈바공 연구소」 → 「바닥 연구소장」 명패
- 움직임: 공통 인트로(tools/video/intro.js). 모든 강좌 영상에 같은 장면을 씀
- 앞멈춤: 0.5초
- 멈춤: 1초

### L03 · 세 친구의 음식 (쇼츠 S1)

- 읽기: 친구 세 명에게 좋아하는 음식을 물어봤어요. [에이|A]는 고기 음식만, [비|B]는 매운 음식만, [씨|C]는 면 요리만 이야기했어요.
- 화면: 그림 knn_fig0_food.png 위쪽(세 친구와 음식)
- 움직임: 친구 A → B → C 순서로 하나씩 등장, 각자 음식 카드가 옆에 붙음

### L04 · 처음 보는 음식 세 개 (쇼츠 S1)

- 읽기: [에이|A], [비|B], [씨|C] 세 친구가 말하지 않은 칼국수, 소불고기, 쭈꾸미볶음은 누가 좋아할까요? 잠깐 멈추고 맞혀 보세요.
- 화면: 그림 knn_fig0_food.png 아래쪽(칼국수·소불고기·쭈꾸미볶음)
- 움직임: 음식 세 개가 차례로 등장, 끝에 3초 카운트다운
- 멈춤: 3초

### L05 · 정답 (쇼츠 S1)

- 읽기: 칼국수는 면 요리라서 [씨|C]예요. 소불고기는 고기 음식이라서 [에이|A]예요. 쭈꾸미볶음은 매운 음식이라서 [비|B]예요.
- 화면: 음식에서 친구에게 화살표
- 움직임: 화살표 세 개가 하나씩 그어짐

### L06 · 어떻게 맞혔을까 (쇼츠 S1 끝)

- 읽기: 방금 어떻게 맞혔는지 떠올려 보세요. 소불고기를 보고 "삼겹살이랑 비슷하네, 그럼 [에이|A]" 하고 생각했을 거예요. 답을 이미 아는 것들 중에서 가장 비슷한 것을 찾아 판단한 거죠. 이게 케이엔엔의 출발점이에요.
- 화면: 소불고기 ↔ 삼겹살 나란히, 사이에 "비슷!" 표시 → A
- 움직임: 두 음식이 서로 끌려와 붙음

### L07 · 애매한 짬뽕

- 읽기: 그런데 짬뽕은 어떨까요? 맵기도 하고 면이기도 해요. [비|B]라고 해도, [씨|C]라고 해도 그럴듯하죠. 이렇게 애매할 때는 얼마나 비슷한지 재는 기준이 필요해요.
- 화면: 짬뽕 하나에서 B와 C 양쪽으로 점선
- 움직임: 짬뽕이 B와 C 사이에서 좌우로 흔들림

### L08 · 과일을 점으로

- 읽기: 이번엔 과일 열두 개의 크기와 당도를 재서 그래프에 점으로 찍었어요. 가로는 크기, 세로는 당도예요. 빨간 동그라미는 사과, 노란 세모는 귤이에요.
- 화면: 그림 knn_fig1_guess.png (별 제외)
- 움직임: 축이 그려진 뒤 점 12개가 하나씩 떨어짐

### L09 · 별은 무엇일까

- 읽기: 파란 별은 정체를 모르는 과일이에요. 사과들 한가운데에 있으니 바로 사과라고 답하게 되죠. 과일을 직접 보지 않았는데도 숫자 두 개만으로 맞혔어요. 비슷한 과일끼리는 그래프에서도 가까이 모이기 때문이에요.
- 화면: 그림 knn_fig1_guess.png
- 움직임: 별 등장 → 주변 사과 점들이 잠깐 반짝임

### L10 · 애매한 별

- 읽기: 그럼 이 별은 어떨까요? 사과도 하나 가깝고 귤도 몇 개 가까워요. 눈으로만 보면 정하기 어려워요. 이럴 때는 거리를 숫자로 재면 돼요.
- 화면: 그림 knn_fig2_ambiguous.png
- 움직임: 별 주변 점선 원이 천천히 커짐

### L11 · 자로 잰 거리

- 읽기: 두 점 사이 거리는 자로 잰 직선 거리라고 생각하면 돼요. 중학교 때 배운 피타고라스 정리로 구해요. 이렇게 잰 거리를 유클리드 거리라고 불러요. 계산하는 방법은 블로그 글에 자세히 적어 두었어요.
- 화면: 두 점 사이에 자가 놓이고 직선이 그어짐, 직각삼각형이 겹쳐 보였다 사라짐
- 움직임: 자가 미끄러져 들어옴

### L12 · 가까운 세 과일과 투표

- 읽기: 별에서 가장 가까운 과일 세 개는 [사과 6번|사과6], [귤 4번|귤4], [귤 6번|귤6]이에요. 거리는 [영 점 이팔|0.28], [영 점 삼이|0.32], [영 점 오사|0.54]예요. 귤이 두 표, 사과가 한 표니까 이 과일은 귤이라고 판단해요.
- 화면: 그림 knn_fig3_distance.png, 오른쪽에 투표판(귤 2 : 사과 1)
- 움직임: 거리 선 세 개가 가까운 순서로 그어지고 숫자가 붙음 → 투표판 칸이 하나씩 채워짐

### L13 · 이름 붙이기

- 읽기: 방금 한 일이 바로 케이엔엔이에요. 정리하면 네 단계예요. 먼저 정답을 아는 데이터를 준비해요. 새 데이터와 모든 데이터 사이 거리를 재요. 가까운 순서로 줄 세워 앞에서 [케이|k] 개를 골라요. 마지막으로 그중 가장 많은 쪽을 답으로 정해요. [케이|k]는 이웃을 몇 개 볼지 정하는 숫자예요. 방금은 [케이|k]가 3이었어요.
- 화면: 단계 카드 4장(준비 → 거리 → 줄 세우기 → 다수결)
- 움직임: 카드가 한 장씩 뒤집힘, 말하는 단계 카드가 강조됨

### L14 · 미리 공부하지 않는 방법

- 읽기: 케이엔엔에는 미리 공부하는 단계가 따로 없어요. 데이터를 저장해 두었다가 새 질문이 들어오는 순간에 거리를 계산하죠. 그래서 인스턴스 기반 학습이라고도 불러요. 이 방법은 1951년 에벌린 픽스와 조지프 호지스가 처음 내놓았다고 알려져 있어요.
- 화면: 데이터 서랍장 → 질문이 들어오면 서랍이 열림, 아래에 「1951 · Evelyn Fix, Joseph Hodges」
- 움직임: 서랍이 열리며 점들이 나옴

### L15 · 짬뽕을 숫자로

- 읽기: 아까 짬뽕도 숫자로 바꿔 볼 수 있어요. 고기인지, 매운지, 면인지를 1과 0으로 적으면 짬뽕은 고기 0, 매움 1, 면 1이에요. 이렇게 재면 [비|B]의 음식들과도, [씨|C]의 음식들과도 거리가 똑같이 1이에요. 애매하다고 느꼈던 이유가 숫자로도 확인되는 거죠.
- 화면: 짬뽕 카드에 (0, 1, 1) → B 쪽 거리 1, C 쪽 거리 1
- 움직임: 숫자 칸이 하나씩 채워짐, 양쪽 거리 표시가 동시에 떠서 저울처럼 수평을 이룸

### L16 · k를 바꾸면 (쇼츠 S2)

- 읽기: 같은 별인데 [케이|k]만 바꿔 볼게요. [케이|k]가 1이면 사과, 3이면 귤, 5면 귤이에요. [케이|k] 하나 바꿨을 뿐인데 답이 달라졌어요.
- 화면: 그림 knn_fig4_k_compare.png, 원이 k=1 → 3 → 5로 커짐, 옆에 판단 결과
- 움직임: 원이 커질 때마다 원 안의 점이 투표판으로 날아감

### L17 · 왜 달라졌을까 (쇼츠 S2 끝)

- 읽기: 가장 가까운 [사과 6번|사과6]은 다른 사과들보다 유난히 작은 사과예요. [케이|k]가 1이면 이 예외 하나만 보고 사과라고 답해 버려요. [케이|k]를 키우면 주변 귤들의 표가 같이 들어와서 이런 예외에 덜 흔들려요.
- 화면: 사과6에 "유난히 작은 사과" 꼬리표
- 움직임: 사과6이 다른 사과들 쪽에서 떨어져 나온 것처럼 보이게 다른 사과들을 흐리게 처리

### L18 · k가 너무 크면

- 읽기: 그렇다고 [케이|k]를 무작정 키우는 게 좋지는 않아요. [케이|k]가 커질수록 잡음에는 강해지지만 무리 사이 경계가 흐려져요. [케이|k]를 전체 개수인 12까지 키우면 별이 어디에 있든 결과가 똑같아져서 거리를 잴 의미가 없어져요. 그래서 알맞은 [케이|k]는 여러 값을 시험해 보고 골라요.
- 화면: 원이 12개를 모두 덮을 때까지 커짐 → 별을 다른 자리로 옮겨도 결과 같음
- 움직임: 별이 그래프 위를 돌아다녀도 투표판 숫자가 그대로

### L19 · 단위가 바뀌면 (쇼츠 S3)

- 읽기: 케이엔엔은 거리로만 판단해서 단위에 민감해요. 새 과일과 비교할 과일이 둘 있어요. [에이|A]는 크기만 1센티미터 다르고, [비|B]는 당도만 2 달라요. 크기를 센티미터로 적으면 [에이|A]까지 거리는 1, [비|B]까지는 2라서 [에이|A]가 더 가까워요.
- 화면: 그림 knn_fig5_units.png 왼쪽(cm)
- 움직임: 거리 선 두 개가 그어지고 A 쪽이 "더 가까움"

### L20 · 밀리미터로 바꾸면 (쇼츠 S3 끝)

- 읽기: 그런데 크기를 밀리미터로 적으면 [에이|A]까지 거리가 10이 되고, [비|B]까지는 그대로 2예요. 이번엔 [비|B]가 더 가까워요. 과일은 그대로인데 단위만 바꿨더니 가까운 이웃이 바뀌었어요. 그래서 케이엔엔을 쓰기 전에는 특징마다 값의 범위를 0에서 1 사이로 맞추는 정규화를 해 줘요.
- 화면: 그림 knn_fig5_units.png 오른쪽(mm), 마지막에 「정규화: 범위를 0~1로」
- 움직임: 가로축이 10배로 늘어나며 A가 멀어짐

### L21 · 동점과 속도

- 읽기: 다른 걸림돌도 있어요. 투표가 동점이 될 수도 있어요. 그래서 두 종류로 나누는 문제라면 [케이|k]를 홀수로 정해요. 가까운 이웃에게 더 큰 표를 주는 방법도 있어요. 또 새 데이터가 올 때마다 저장된 모든 데이터와 거리를 재야 해요. 그래서 데이터가 많으면 느려져요. 실제로는 케이디 트리 같은 자료 구조나 근사 탐색으로 계산을 줄여요.
- 화면: 투표판 동점 → 홀수 k / 점이 수천 개로 늘어나며 계산 표시가 쌓임
- 움직임: 점 개수가 빠르게 늘어남

### L22 · 특징이 너무 많으면

- 읽기: 특징이 크기와 당도처럼 두세 개일 때는 거리가 잘 작동해요. 그런데 특징이 아주 많아지면 점들 사이 거리 차이가 잘 드러나지 않아 성능이 떨어질 수 있어요. 이걸 차원의 저주라고 불러요.
- 화면: 축이 2개 → 여러 개로 늘어나며 점들이 고르게 퍼짐
- 움직임: 점들 사이 거리 숫자가 비슷비슷해짐

### L23 · 장점과 단점

- 읽기: 정리해 볼게요. 케이엔엔은 원리가 단순하고, 미리 학습하는 단계가 없고, 어느 이웃을 보고 그렇게 판단했는지 그대로 보여 줄 수 있어요. 대신 데이터가 많으면 느리고, 단위에 민감하고, [케이|k]를 직접 정해야 해요. 그래서 데이터가 아주 많지 않고 특징이 몇 개 안 될 때 먼저 시도해 보기 좋은 방법이에요.
- 화면: 왼쪽 장점 3칸, 오른쪽 단점 3칸
- 움직임: 말하는 항목이 차례로 켜짐

### L24 · 실생활에서

- 읽기: 가장 가까운 것을 찾는다는 생각은 생활 곳곳에서 쓰여요. 아마존은 2003년 논문에서 함께 사는 고객이 많은 상품끼리 가깝다고 보고 추천하는 방법을 공개했어요. 스포티파이는 비슷한 곡을 빠르게 찾으려고 애노이라는 도구를 만들어 공개했고요. 검색 엔진 일래스틱서치는 질문과 가장 가까운 글을 찾는 기능을 아예 케이엔엔 검색이라는 이름으로 제공해요.
- 화면: 그림 life_knn.png, 쇼핑 → 음악 → 검색 순서
- 움직임: 세 칸이 차례로 확대

### L25 · 한 줄 요약

- 읽기: 한 줄로 정리하면 케이엔엔은 새 데이터와 가장 가까운 [케이|k] 개의 이웃을 찾아 그 이웃들의 다수결로 답을 정하는 방법이에요.
- 화면: 요약 문장 한 줄, 아래에 별과 이웃 3개 그림
- 움직임: 문장이 단어 단위로 나타남

### L26 · 퀴즈

- 읽기: 마지막으로 퀴즈 하나예요. [케이|k]가 3일 때 가장 가까운 이웃이 사과, 귤, 귤이었어요. 케이엔엔은 뭐라고 답할까요?
- 화면: 퀴즈 카드, 이웃 셋(사과·귤·귤)이 말할 때 하나씩 → 3초 카운트다운
- 움직임: 이웃 칩이 차례로 들어옴
- 멈춤: 3초

### L26B · 퀴즈 정답

- 읽기: 정답은 귤이에요. 귤 두 표, 사과 한 표로 다수결에서 귤이 이겨요.
- 화면: 투표판 귤 2 : 사과 1 → 「귤!」
- 움직임: 표가 하나씩 쌓임

### L27 · 마무리와 블로그 안내

- 읽기: 오늘은 개념까지 살펴봤어요. 열두 개 과일과의 거리 전체 표와 정규화 계산 방법은 설명란의 블로그 글에 정리해 두었어요. 다음 영상에서는 점들 사이에 가장 잘 맞는 직선을 긋는 선형 회귀를 다뤄요.
- 화면: 블로그 글 화면 미리보기 + 「설명란 링크」, 다음 영상 카드
- 움직임: 진행자 캐릭터가 설명란 방향을 가리킴

## 쇼츠 전용 장면

### S1E · 쇼츠 S1 마무리 (L06 대신, 짬뽕 질문으로 끝냄)

- 읽기: 방금 어떻게 맞혔는지 떠올려 보세요. 소불고기를 보고 "삼겹살이랑 비슷하네, 그럼 [에이|A]" 하고 생각했을 거예요. 답을 이미 아는 것들 중에서 가장 비슷한 것을 찾아 판단한 거죠. 이게 인공지능의 기초 알고리즘인 케이엔엔의 시작이에요. 그럼 매운 음식이기도 하고 면 요리이기도 한 짬뽕은 누가 좋아할까요? 케이엔엔 알고리즘으로 판단해 볼까요?
- 화면: L06 화면 그대로 → 「= 인공지능 기초 알고리즘 kNN의 시작」 → 짬뽕 카드가 B와 C 사이에 나타나고 양쪽으로 점선, 큰 물음표
- 움직임: 짬뽕 카드가 B와 C 사이에서 좌우로 흔들림. 마지막 문장 "케이엔엔 알고리즘으로 판단해 볼까요?"를 말할 때 끝 안내 화면(짬뽕의 답은 관련 동영상에서)이 덮이고, 말이 끝나고 0.8초 뒤 영상 끝

### S2E · 쇼츠 S2 마무리 (L17 뒤에 붙임)

- 읽기: 그럼 [케이|k]를 아주 크게 키우면 더 정확해질까요? 케이엔엔 알고리즘으로 확인해 볼까요?
- 화면: 원이 점점 커지며 과일을 모두 덮음, 「k를 키울수록 좋을까?」
- 움직임: 원이 커짐. "케이엔엔 알고리즘으로"부터 끝 안내 화면

### S3E · 쇼츠 S3 마무리 (L20 대신)

- 읽기: 그런데 크기를 밀리미터로 적으면 [에이|A]까지 거리가 10이 되고, [비|B]까지는 그대로 2예요. 이번엔 [비|B]가 더 가까워요. 과일은 그대로인데 단위만 바꿨더니 가까운 이웃이 바뀌었어요. 그럼 단위가 다른 특징은 어떻게 맞춰야 할까요? 케이엔엔 알고리즘으로 알아볼까요?
- 화면: L20 화면 그대로 → 「단위가 다르면 어떻게 맞출까?」
- 움직임: "케이엔엔 알고리즘으로"부터 끝 안내 화면
